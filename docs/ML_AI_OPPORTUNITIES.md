# KIRO Platform — где и как внедрить ML/AI

**Дата:** 27.10.2026 · Дополняет [PLATFORM_AUDIT_V1_TO_V2.md](PLATFORM_AUDIT_V1_TO_V2.md)

Документ для продукта и ML/AI-разработчиков: какие данные у нас уже есть, какие функции можно построить, как именно (модели, архитектура), какие задачи поставить команде и в каком порядке. Оценки эффекта — **гипотезы**, их нужно проверять экспериментами (A/B), а не принимать на веру.

> **Что проверено по коду, а что нет.** Перечень данных и узких мест взят из репозитория. Объёмы данных на проде (число пользователей, сдач ДЗ, сообщений) в репозитории неизвестны — локальная БД содержит 2 тестовых пользователя. От реальных объёмов зависит выбор между «взять готовую LLM по API» и «обучать свою модель»; это первый вопрос к команде.

---

## 1. Резюме

Самый ценный ресурс платформы — **цикл «ученик сдаёт ДЗ → человек проверяет → ученик дорабатывает»**. Сегодня он целиком ручной: проверяющие читают каждое решение, ученик ждёт обратной связи. Это и главное узкое место масштабирования (число проверяющих растёт линейно с числом учеников), и самая очевидная точка для AI.

Приоритеты по соотношению эффект/сложность:

1. **AI-ассистент проверки ДЗ** — предварительная проверка кода/текста, черновик комментария для проверяющего; снимает 50–70 % рутины (гипотеза).
2. **AI-наставник в уроке (Socratic tutor)** — отвечает на вопросы по материалам курса, не выдавая готовое решение (RAG по нашему контенту).
3. **Персональная траектория и рекомендации** — что учить дальше, какие задачи повторить, адаптивный тест уровня.
4. **Прогноз оттока и «раннее предупреждение»** — кому нужна помощь куратора до того, как человек исчез.
5. **Модерация и безопасность сообщества** (токсичность, спам, фото анкет) — нужна уже сейчас из-за стены, личных сообщений и раздела «Знакомства».
6. **Генерация и контроль качества контента** — квизы, варианты задач, проверка уроков на ошибки.
7. **Аналитика и поиск** — семантический поиск по материалам, автосводки для кураторов.

Важное предупреждение: AI-функции ставят **новые требования к безопасности и приватности** (раздел 8) — решения учеников и сообщения нельзя отправлять внешним провайдерам без согласия и политики данных.

**Пробелы в данных (их надо закрыть до ML):**
- аналитика лежит в той же SQLite без единой схемы событий и без хранилища (см. аудит, раздел 5) — нужен пайплайн сбора (ClickHouse/витрины);
- нет явной «карты знаний»: к какой теме/навыку относится каждая задача, вопрос и глава. Без разметки навыками ни рекомендации, ни модель знаний не заработают — это **первая задача для методистов и ML вместе**;
- нет обратной связи по качеству AI (кнопки 👍/👎, «это помогло?»), нет логирования ответов модели;
- нет согласий на использование данных для обучения/анализа.

## 4. Направления внедрения (подробно)

### 4.1 AI-ассистент проверки домашних заданий  ⭐ приоритет №1

**Проблема.** Проверка ДЗ — ручная и масштабируется только наймом. Ученик ждёт ответа часами или днями; качество комментариев зависит от проверяющего.

**Что делаем (по этапам).**

1. **Черновик для проверяющего (human-in-the-loop).** При сдаче решения система автоматически:
   - запускает код в песочнице на тестах (для Python — серверная песочница, для SQL — уже есть `sqlTrainer`), собирает результат;
   - вызывает LLM с контекстом: условие задачи, эталонные критерии, решение, результаты тестов, 3–5 похожих прошлых проверок (few-shot из `homework_reviews`);
   - выдаёт проверяющему **предлагаемый вердикт + черновик комментария + список замечаний с привязкой к строкам**. Проверяющий принимает/правит одним кликом.
2. **Мгновенная обратная связь для ученика (без вердикта).** Пока решение ждёт человека — ученик получает подсказки по стилю, типичным ошибкам, сложности (без раскрытия решения); можно запросить до N подсказок.
3. **Автоодобрение простых случаев** — когда тесты пройдены, уверенность высокая и задача из «безопасного» класса, решение утверждается автоматически, с выборочной проверкой человеком (5–10 %).
4. **Антиплагиат/анти-копирование.** Схожесть решений (эмбеддинги + AST-хеши), сигнатуры текстов LLM-генерации. Это сигнал для проверяющего, а не наказание.

**Техника.** LLM через API (или self-hosted open-weight) + структурированный вывод (JSON-схема: `verdict`, `confidence`, `issues[]`, `comment`). Оценка качества: сравнение с вердиктами людей на историческом датасете (precision/recall по классу `approved`). Порог автоодобрения подбирается так, чтобы доля ложных одобрений была ≤ 1–2 %.

**Метрики.** Время до первой обратной связи, доля решений, где проверяющий принял черновик без правок, нагрузка на проверяющего (минут на решение), доля повторных `rework`, CSAT ученика.

**Риски.** Галлюцинации модели (всегда показывать вердикт AI как рекомендацию), prompt-injection через текст решения (решение — это данные, не инструкции; изоляция промпта), утечка эталонов, приватность (раздел 8).

### 4.2 AI-наставник в уроке (RAG-тьютор)

**Идея.** Кнопка «Спросить» рядом с теорией, ДЗ и тренажёром. Наставник отвечает по **нашим материалам**, ссылается на раздел и подсказывает шаг, а не готовый ответ.

**Как.**
- Индексация контента: чанки теории/глав/квизов → эмбеддинги → векторный индекс (pgvector в PostgreSQL на первом этапе, потом отдельный Qdrant/Weaviate при росте).
- Контекст запроса: текущий урок, задача, прогресс ученика, последние ошибки.
- Режимы: «объясни проще», «приведи пример», «наводящий вопрос», «проверь моё понимание». Для ДЗ — **ступенчатые подсказки** (уровень 1: направление, 2: идея, 3: псевдокод; решение — никогда).
- Ответ всегда с источником (ссылка на раздел) и пометкой «AI может ошибаться».
- Для кода: запуск примера в песочнице, чтобы не выдавать нерабочий код.

**Метрики.** Доля вопросов, закрытых без куратора; удержание после использования; доля подсказок, после которых ученик решил задачу сам; доля 👎.

### 4.3 Персонализация: модель знаний, рекомендации и адаптивный тест

**Модель знаний ученика (knowledge tracing).** По ответам на квизы, запускам кода, сдачам ДЗ оцениваем вероятность владения каждым навыком. Начать с простого: Bayesian Knowledge Tracing / Elo-подобный рейтинг навыков и задач; затем — DKT/SAKT (нейросетевые модели), если данных достаточно (десятки тысяч ответов).

**Что получает пользователь.**
- «Что учить дальше» на дашборде: следующий урок, повторение забываемого (интервальные повторения по кривой забывания), задачи нужной сложности.
- **Адаптивный тест уровня** (сейчас `LevelTest` — фиксированный): модель IRT (item response theory) подбирает следующий вопрос по предыдущим ответам — тот же результат за 8–10 вопросов вместо длинного теста.
- Подбор программы/направления при онбординге (backend / ML / аналитика / безопасность…) по ответам и целям.
- Рекомендации вакансий по навыкам (`vacancies` ↔ карта навыков) и «чего не хватает до этой вакансии».

**Предусловие.** Размеченная карта навыков (раздел 2) и калибровка сложности задач по историческим данным.

### 4.4 Прогноз оттока и раннее предупреждение

**Задача.** Предсказать, что ученик «уйдёт» (нет активности N дней, не сдаёт ДЗ) за 7–14 дней до события.

**Признаки.** Частота и давность визитов, активное время, серия дней, динамика сдач, доля `rework`, скорость ответа проверяющих, соц.активность, время суток/устройство.

**Модель.** Градиентный бустинг (LightGBM/CatBoost) — быстрый, интерпретируемый (SHAP); не нужна нейросеть. Таргет — «неактивен 14 дней» (в когорте).

**Что делаем с прогнозом.** Список «в зоне риска» для кураторов; автоматические мягкие сообщения (напоминание, ссылка на лёгкую задачу, предложение созвона); эксперимент: контрольная группа без вмешательства — чтобы доказать эффект (uplift-моделирование).

### 4.5 Модерация и безопасность сообщества

Есть публичная стена, комментарии, личные сообщения и раздел «Знакомства».

- **Текст:** классификатор токсичности/оскорблений/спама/мошенничества/персональных данных (дообученная русскоязычная модель или API модерации); действия: скрыть и отправить на ручную проверку, предупреждение автору, лимиты на повторы.
- **Изображения:** NSFW/насилие, детектирование лиц на фото анкет, проверка, что фото — не чужое/не стоковое (по необходимости).
- **Анти-абьюз:** обнаружение ботов и мультиаккаунтов (поведенческие признаки), аномалии регистраций (связано с задачей S3 из аудита).
- **Защита детей/несовершеннолетних:** если среди участников есть несовершеннолетние, раздел знакомств требует отдельного решения команды и юристов; модерация не заменяет правила доступа.

### 4.6 Генерация и качество контента

- **Генерация вариантов задач и квизов** из существующих (параметризация числовых значений, другие формулировки) — меньше списывания, больше практики. Каждую сгенерированную задачу проверяет автотест/проверяющий перед публикацией.
- **Автогенерация вопросов по тексту урока** + дистракторы; очередь на модерацию методистом.
- **Проверка контента на ошибки:** противоречия, устаревшие версии библиотек, битые ссылки, непокрытые темы.
- **Аналитика качества задач:** «задачу не решает никто», «слишком лёгкая», «неоднозначное условие» (по статистике ответов и вопросам к наставнику).
- **Конспекты и карточки для повторения** (flashcards) из теории, персонально под слабые места.
- **Мультиязычность:** перевод материалов с проверкой терминологии.

### 4.7 Код-тренажёры нового уровня

- **Объяснение ошибки** в Python/SQL: человеческим языком, привязка к строке, пример исправления (на базе трассировки + LLM).
- **Отладчик-тьютор:** шаг за шагом объясняет исполнение (расширение `AlgoViz`).
- **Автогенерация тест-кейсов** и мутационные тесты для проверки того, что решение ученика не «хакает» тесты.
- **Оценка сложности и стиля решения** (читаемость, асимптотика) — для обратной связи и портфолио.
- **SQL:** подсказки по плану выполнения, сравнение результата с эталоном по семантике.

### 4.8 Карьерные и «софт»-функции

- **Голосовой/текстовый тренажёр собеседований** (в программах уже есть «likbez» и интервью-квизы): ИИ-интервьюер задаёт вопросы по направлению, оценивает ответ по рубрике и даёт разбор; запись лучших попыток в портфолио.
- **Разбор резюме и сопроводительных писем** под вакансию из раздела «Вакансии».
- **Генерация портфолио-описаний проектов** из репозитория/сданных ДЗ.
- **Симуляция командной работы:** AI-«тимлид»/«заказчик» для проектов (программы product, business, system analyst).
- **Прогноз «готов ли к стажировке»** по прогрессу и результатам проекта.

### 4.9 Социальная часть и вовлечение

- **Рекомендации людей и постов** («с кем учиться»): граф подписок + схожие навыки/цели; соблюдение приватности.
- **Подбор пар для код-ревью и study buddy** по уровню и времени активности.
- **Дайджесты** («что пропустил за неделю»), персонализированные уведомления с оптимальным временем отправки.
- **Антиспам и качество ленты:** ранжирование постов по полезности, а не только по времени.

### 4.10 Операции и аналитика для команды

- **Семантический поиск** по материалам, вопросам, архиву сообщений для кураторов.
- **Автосводки:** «что произошло с когортой за неделю», «топ-5 мест, где ученики застревают» — на основе аналитики и вопросов к наставнику.
- **Анализ отзывов и комментариев** (тональность, темы жалоб).
- **Прогноз нагрузки проверяющих** и автоматическое распределение проверок (очередь с приоритетами: срок ожидания, «сложность» решения, опыт проверяющего).
- **Оптимизация расписания созвонов** (прогноз посещаемости, подбор слотов по часовым поясам и занятости).
- **Поддержка пользователей:** чат-бот по FAQ платформы (вход, доступы, расписание) с передачей оператору.
- **Аномалии в метриках и безопасности:** подозрительные входы, всплески ошибок, массовые запросы к API.

## 6. Целевая архитектура AI-слоя

```
Web / Admin ──► API Gateway ──► AI Gateway (отдельный сервис)
                                   │  • авторизация и квоты на пользователя
                                   │  • маскирование PII, фильтры входа/выхода
                                   │  • маршрутизация по моделям, кэш, ретраи, fallback
                                   │  • логирование промптов/ответов (с TTL), оценка стоимости
                                   ├──► LLM-провайдеры (API) / self-hosted модели (vLLM)
                                   ├──► Векторный индекс (pgvector → Qdrant)
                                   ├──► Песочница исполнения кода (Python/SQL)
                                   └──► Очередь задач (асинхронные проверки ДЗ, генерация)

Событийная шина ──► Хранилище аналитики (ClickHouse) ──► Feature store ──► ML-сервис (batch/online-инференс)
                                                          └─► Обучение моделей (MLflow, реестр моделей)
Мониторинг качества: оценки (evals), дрейф данных, 👍/👎, стоимость, латентность, доля отказов
```

Ключевые решения:

- **AI Gateway как единая точка** — централизует безопасность, лимиты, стоимость и подмену модели без правок продукта.
- **Два режима**: онлайн (наставник, подсказки — секунды, стриминг) и офлайн (проверка ДЗ, генерация контента, батчи — очередь).
- **Эвалы до релиза.** Для каждой AI-функции собираем золотой набор примеров (из `homework_reviews`, вопросов методистов) и прогоняем при каждой смене промпта/модели. Без этого регрессии не заметны.
- **Human-in-the-loop по умолчанию**, автоматика — только после измеренной точности.
- **Дообучение** своих моделей — после накопления данных; сначала промпт-инжиниринг + RAG + few-shot, потом — LoRA/fine-tune открытой модели, если нужно снизить стоимость или хранить данные в РФ.
- **Выбор моделей.** Закрытые API — быстрый старт; открытые (Qwen, Llama, Mistral и т. п.) на своём GPU — приватность и контроль цены при больших объёмах. Решение принимать по замеру качества на наших эвалах и по юридическим требованиям, а не по рекламе.
- **Стоимость.** Закладывать бюджет на токены на пользователя, кэшировать повторяющиеся запросы, использовать маленькие модели для классификации и большие — для объяснений.

## 7. Задачи для ML/AI-разработчиков

### 7.1 Инфраструктура и данные (старт)
- Спроектировать единую схему событий и витрины (совместно с аудитом, раздел 7.6), настроить выгрузку в ClickHouse/Parquet.
- Подготовить датасеты: решения + вердикты + комментарии (обезличенные); вопросы + ответы; траектории по урокам.
- Собрать **карту навыков** вместе с методистами: таксономия тем, привязка к задачам/вопросам/главам.
- Развернуть MLflow, реестр моделей, feature store (на старте — таблицы в PostgreSQL/ClickHouse).
- Построить **AI Gateway** с логированием, квотами, маскированием PII.
- Настроить эвалы: набор «золотых» кейсов и автоматический прогон.

### 7.2 Ядро продукта
- **Проверка ДЗ:** пайплайн «песочница → тесты → LLM → черновик»; структурированный вывод; калибровка порога уверенности; интеграция в интерфейс проверяющего (принять/править/отклонить).
- **RAG-наставник:** чанкинг материалов, эмбеддинги, гибридный поиск (BM25 + вектор), ступенчатые подсказки, ссылки на источники, защита от prompt-injection.
- **Модель знаний и рекомендации:** BKT/Elo → DKT; калибровка сложности; интервальные повторения; адаптивный тест (IRT).
- **Прогноз оттока:** признаки, LightGBM, SHAP, uplift-эксперименты, интеграция «Куратор-радар».
- **Модерация:** классификаторы текста, NSFW для изображений, правила эскалации.

### 7.3 Расширения
- Антиплагиат (AST + эмбеддинги), детектор LLM-текстов.
- Генерация задач/квизов с автопроверкой и очередью модерации.
- Mock-интервью (ASR/TTS + рубрики оценки).
- Матчинг вакансий и резюме, Skill Passport.
- Рекомендации людей/постов, study buddy.
- Анализ отзывов, автосводки для кураторов, чат-бот поддержки.
- Планирование проверок и созвонов (оптимизация очереди и слотов).

### 7.4 Качество и эксплуатация
- Мониторинг дрейфа данных и качества моделей, алерты по деградации.
- Контроль стоимости (токены на пользователя/функцию), кэширование, роутинг по моделям.
- A/B-платформа для AI-функций, метрики успеха на каждую.
- Red-teaming: prompt-injection через решения и посты, jailbreak, утечка системных промптов и эталонов.
- Документирование: карточки моделей (model cards), версии промптов, процедура отката.

## 8. Безопасность, приватность и этика (обязательно до запуска)

- **Данные учеников** (решения, сообщения, анкеты) — персональные. Любая отправка внешнему провайдеру требует: согласия пользователей, договора с провайдером (запрет обучения на данных), маскирования PII, а для РФ — оценки по 152-ФЗ (хранение и трансграничная передача). Для чувствительных задач предпочтителен self-hosted инференс.
- **Не использовать личные сообщения и анкеты знакомств** для обучения или рекомендаций без явного согласия; по умолчанию — исключены.
- **Prompt-injection:** решения, посты и сообщения — недоверенный ввод; AI не должен выполнять действия (менять статусы, писать пользователям) без проверки правил на сервере; выходы модели валидируются схемой.
- **Утечка эталонов и системных промптов:** наставник не имеет доступа к скрытым решениям, кроме случаев проверки в изолированном контуре.
- **Справедливость и прозрачность:** AI-вердикт — рекомендация; ученик может оспорить и попросить человека; пользователю явно сообщаем, что отвечает AI.
- **Дети:** если есть несовершеннолетние — ужесточить фильтры, запретить персонализацию по чувствительным признакам, согласие родителей.
- **Академическая честность:** политика использования AI учениками (что разрешено), инструменты, которые поощряют обучение, а не копирование.
- **Аудит и логи:** хранить промпты/ответы ограниченное время (TTL), доступ только по ролям, журнал обращений.
- **Стоимость и устойчивость:** лимиты на пользователя, graceful degradation — платформа обязана работать без AI.

## 9. Дорожная карта

| Этап | Срок | Содержание | Результат |
|---|---|---|---|
| **0. Основа** | 2–4 недели | Согласия и политика данных; схема событий; датасеты; AI Gateway (минимальный); эвалы; карта навыков (черновик) | Можно безопасно пробовать AI |
| **1. Быстрые победы** | 1–2 месяца | Черновик проверки ДЗ для проверяющих; RAG-наставник (пилот на 1–2 программах); модерация текста; объяснение ошибок кода | Сокращение времени проверки, первые данные о пользе |
| **2. Персонализация** | 2–4 месяца | Модель знаний, «что дальше», умные повторения, адаптивный тест; прогноз оттока + Куратор-радар; генерация квизов с модерацией | Рост удержания и завершаемости |
| **3. Расширение** | 4–8 месяцев | Автоодобрение простых ДЗ; антиплагиат; mock-интервью; Skill Passport и вакансии; рекомендации людей; чат-бот поддержки | Новые продукты и ценность для работодателей |
| **4. Зрелость** | 8+ месяцев | Собственные модели (дообучение), оптимизация затрат, голосовой интерфейс, мобильный клиент, планирование ресурсов | Контроль цены и качества |

**Зависимости.** Многие пункты опираются на работы из аудита: PostgreSQL + аналитическое хранилище + очередь (этап 1–2 аудита), единая модель ДЗ и прогресса, серверная проверка доступа к контенту. Пилоты (этап 1) можно запускать раньше на текущей архитектуре через отдельный сервис, но без нормальной модели данных долго держаться они не будут.

## 10. Метрики успеха

| Область | Метрика | Ориентир (гипотеза, проверить A/B) |
|---|---|---|
| Проверка ДЗ | Медианное время до первой обратной связи | с часов/суток до минут |
| | Минут проверяющего на решение | −50 % |
| | Доля принятых черновиков без правок | ≥ 60 % |
| | Доля ложных автоодобрений | ≤ 1–2 % |
| Наставник | Доля вопросов, решённых без куратора | ≥ 50 % |
| | Доля ответов с 👎 | ≤ 10 % |
| Обучение | Завершаемость глав/программ | +10–20 % относительно контроля |
| | Retention D7/D30 | +5–10 п.п. |
| Отток | AUC модели прогноза | ≥ 0,75 |
| | Возврат ученика после вмешательства (uplift) | значимо > контроля |
| Модерация | Доля токсичного контента, дошедшего до ленты | ↓ в разы; ручные проверки — только спорные |
| Бизнес | Конверсия из пробного в платный, NPS | рост относительно контроля |
| Стоимость | Расходы на AI в расчёте на активного ученика | в рамках утверждённого бюджета |
